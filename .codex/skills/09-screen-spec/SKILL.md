# Skill 09: 화면 명세서 (Screen Specification)

## 목적
각 화면에 무엇이 있고, 어떤 상태를 가지며, 어떤 행동이 가능한지를 정의한다.
UI 구현자가 추측 없이 그릴 수 있게 만드는 설계도다.

> **상태 문구는 창작이 아니라 인용이다.** 빈 상태·로딩·에러 문구의 원천은 `PRD_기능상세.md`의 「예외 처리」와 `PRD_검증.md`의 `EC-##`(사용자 영향·처리 방법)다. **원천이 없으면 지어내지 말고 출처 칸을 비운 채 미결(❓)로 올린다** — 다 채워진 화면 명세가 빈칸 있는 것보다 나쁘다.

> **진행 모드별 깊이:** **Quick** 모드에선 방향·플로우 확인에 필요한 화면·핵심 항목까지만 경량으로 명세하고 저해상도 와이어프레임으로 넘어간다. **Full** 모드에선 화면당 5항목(데이터·액션·상태·입력 규칙·연결)을 완결한다. (CLAUDE.md "진행 모드 선택" 참조)

---

## 실행 프로토콜

### Step 1: 화면 우선순위 결정

한 번에 전체를 만들지 말고 순차 생성.

1. 사용자 플로우에서 먼저 등장하는 화면
2. 기능 밀집도가 높은 화면
3. 예외 처리가 많은 화면

### Step 2: 화면 항목 정의

각 화면은 필수로 5가지를 작성:

1. **표시 데이터**: 항목 단위로 구체 작성
2. **사용자 액션**: 목적지/결과/제약 포함
3. **상태**: 로딩/빈값/오류/성공 — **각 문구마다 출처(`REQ-###`·`EC-##`)를 함께 적는다**
4. **입력 규칙**: 필수/선택, 유효성, 에러 메시지 — **에러 메시지도 출처를 적는다**
5. **연결 정보**: REQ-ID/SC-ID/TC-ID

### Step 3: 예외/오류의 미세 명세

성공 플로우만 쓰지 않는다. **각 항목의 문구는 PRD 세트에서 가져오고 출처를 단다.**
- 네트워크 실패 메시지 텍스트
- 동시성 충돌 메시지 텍스트
- 입력 검증 실패 메시지 텍스트
- 권한/세션 만료 처리

### Step 3.5: UX 렌즈 점검 (스킬 16)

화면 항목을 확정하기 전 렌즈로 훑고, 판정을 **세어서** 적는다("직관적" ❌ / "3화면 이동·필수 입력 4개" ✅). 정본은 `.claude/skills/16_ux_principles.md`.

- **가시성:** 이 화면만 보고 현재 위치·가능한 액션·다음 단계를 알 수 있는가? 처리 중·완료·실패 상태가 화면에 드러나는가?
- **효율성:** 목표 달성까지 필요한 입력·클릭이 몇 개인가? 반복 작업에 기본값·직전 값이 있는가?
- **참여도:** 성공·실패 문구가 "무슨 일이 일어났고 다음에 뭘 하면 되는지"를 말하는가?
- **발견 처리:** 개선점 중 REQ·EC 근거가 없는 것은 **명세에 쓰지 말고** 미결(❓)로 올린다 — 출처 칸이 빈 항목은 우리가 지어낸 것이다.

### Step 4: 추적성 점검

작성 완료 전 아래를 점검:
- 해당 화면의 `REQ-###` 목록이 PRD에 존재하는가?
- 각 액션이 플로우의 SC-ID 이동 규칙과 일치하는가?
- 각 상태별 문구가 테스트 케이스(TC-###)로 연결되는가?
- **모든 상태·에러 문구에 출처(`REQ-###`·`EC-##`)가 적혔는가?** 빈칸이면 그 문구는 **우리가 지어낸 것**이다 — 지우거나 미결로 올린다
- 적은 `REQ-###`가 PRD에 실제로 있는가? (`validate_traceability.py`가 유령 참조를 ❌로 잡는다)

## 완성 체크리스트

- 서비스 구조도의 모든 화면에 명세가 있는가?
- 모든 액션에 목적지(이동/결과)가 명시되었는가?
- 빈 상태/로딩/에러 상태가 모두 정의되었는가?
- **모든 상태·에러 문구에 출처가 적혔는가?** — 빈 출처 칸은 **지어낸 문구**라는 신호다
- 표시 데이터가 구체적인가? ("문의 정보" ❌ → "인입 시각, 채널, 고객명, 문의 유형" ✅)
- REQ/SC/TC 매핑이 모두 존재하는가?
- **이 화면만 보고 현재 위치와 다음 단계를 알 수 있는가?** (가시성 — 스킬 16)
- **목표까지의 필수 입력·클릭 수를 세어 적었는가?** (효율성)
- **성공·실패 피드백이 다음 행동을 안내하는가?** (참여도)
- **REQ 근거 없는 UX 개선을 명세에 임의로 넣지 않고 미결로 올렸는가?** (스킬 16 `UX 발견 처리 규칙`)
